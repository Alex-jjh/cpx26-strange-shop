# Strange Shop 奇怪小店（CPX 2026 · 赛道二 逆向 UX）

一家看起来很普通的网店。可你一点「立即购买」，它就把这次购买变成一份采购申请：先关广告、填申请单、等 AI 领导审批，再做一张复核单，最后才能模拟下单。

团队分工和分支流程见 [docs/TEAM.md](docs/TEAM.md)；AI 助手的规则见 [AGENTS.md](AGENTS.md)。
文献清单和论文 PDF（Git LFS）在 [paper/](paper/README.md)。

## 两个视觉世界

- **购物世界**（商品列表、商品页）：暖色橙红、大红价格、白色商品卡、底部固定的「立即购买」栏。它是**滑梯**，顺滑、诱人。
- **审批世界**（转办页、广告之后的所有页面）：灰白公文，带文号、审批人「AI 领导」、红色圆形印章（驳回/同意）。它是**墙和问题**。
- 点「立即购买」不付款，直接换成审批世界。这一下视觉切换，就是"在滑梯上放一个问题"。设计细则见 [docs/ui-design.md](docs/ui-design.md)。

## 路演流程（已用自动化走通）

1. 首页（橙红购物风格）点「米家投影仪 青春版2」（2699 元）→ 点底部「立即购买」。不会付款：页面换成灰白公文风格的转办页「您的购买请求已转为采购申请」（带文号和审批人「AI 领导」）→「开始办理」→ 摇一摇（或点击）关闭全屏广告 → 保持手机平稳 3 秒 →「理性尚存，继续填表」。
2. 申请单全部点选：用途「和朋友、家人一起用」，首次使用「本周内」，频率「只用一次」，替代方案不选（或「为什么不租」选「没想过可以租」），总价填标价 2699 → 提交。
3. **被驳回**：总价没算配件和运费；只用一次，为什么不租？替代方案一项都没论证。
4. 补充材料：频率改「每周」，「为什么不租」选「要长期用，租金会超过买价」，「为什么不借」选「身边没人有」，总价改为 2728.90（标价 + 必需的 HDMI 线 29.90，免运费）→ 再次提交。
   想多一个笑点：用途选「别人都有了」，会被第二条驳回「不是用途，是借口」。
   同类投影仪日租只要 10 元（3 天起租），所以第 3 步的「为什么不租？」很有说服力。
5. 审批通过 →「去下单」→ **复核单**：第 1 题「租满多少天才追上买的钱」（答案 273 天，可以故意先选错，演示退回重做），第 2 题核对频率（每周），第 3、4 题选「在角落安静吃灰」「想不起来买过什么」→ 领导批示中 → 审批回执（带印章和 AI 批示）。
6. 「返回首页」→ 再点那台投影仪 →「立即购买」→ 点顶上的「不买了」：一点就走，不挽留，显示「本次省下 ¥2728.90」。这是 reverse 的另一半：买要过问题，不买随时可以走。

完整逐字稿见 [docs/pitch.md](docs/pitch.md)。

## 关键设计

- **Reverse 的是方向**：普通购物 App 让买很容易、不买很难。奇怪小店反过来：买之前要过申请单和复核单，审批世界的每一页顶上都有「不买了」，一点就走，不弹确认。

- **批还是不批由规则决定**（`src/domain/review.ts`），保证演示稳定。每次调用 AI 都会在 Vercel Logs 里留一行结构化日志（搜 `leader-voice`），包括输入、输出、耗时和 token 用量；Hobby 套餐日志只保留约 1 小时。LLM 只把驳回意见改写成"领导口吻"；断网或没配 key 时退回规则原文，流程不受影响。
- 审批规则（普通档）：用途要选具体场景（「先买来试试」「别人都有了」算借口）；总价含必需配件和运费；租、借、现有替代至少 1 项选真实理由（「没想过」不算，「就是想要」算敷衍）；只用一次或每月一次、且能租的商品，「为什么不租」必须选真实理由；选「其他」时手写说明有字数要求；**挑不出毛病的首次申请也会按惯例退回一次**，原样再交即可。
- 「难缠领导」档额外检查：首次使用须在两周以内；替代方案至少 2 项选真实理由。
- 每条规则对应《个人钱包管理暂行办法》的一个条款（`src/domain/regulations.json`），驳回原文和 AI 领导都按条款号引用；App 顶栏「规章」可查看全文。**改条款措辞只需改这个 JSON**，测试会检查每条规则都有且只有一个条款。
- 设备能力（震动、通知、摇一摇）统一走 `src/device/`。App 里调 Capacitor 插件，网页里调浏览器接口，不支持就静默跳过。
- 商品数据：25 款真实报价，由 A 角色在 `CRAZYMIKE/` 采集整理（来源、证据、租赁调查、校验脚本都在里面，见 `CRAZYMIKE/README.md`）。应用读取的副本是 `src/data/products.json` 和 `src/data/product-details.json`，**不要手改副本**：改 `CRAZYMIKE/` 里的研究输入，再运行 `python3 CRAZYMIKE/scripts/build_package.py` 生成，CI 会运行 `CRAZYMIKE/validate.py` 检查两边一致。

## 开发

```bash
npm install
npm run dev       # 本机 http://localhost:5173
npm test          # 规则与数据测试
npm run build
```

手机真机调试不要用 `--host` 暴露到局域网。请部署一个 Vercel 预览地址（自带 HTTPS，摇一摇也需要 HTTPS）。

## 部署（Vercel）

1. 导入仓库，框架选 Vite。
2. 在项目环境变量里配置 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`（见 `.env.example`）。**key 只放服务端，绝不能放进前端或提交到仓库。**
3. 在模型平台上给这个 key 设一个消费上限。`api/leader-voice.ts` 的限流只是尽力而为，按实例计数。

`api/leader-voice.ts` 是公开接口（评委扫码就能用），但不是通用 LLM 代理：只接受固定的规则编号和不超过 40 字的商品名，提示词在服务端拼出来。

## 安卓 APK（Capacitor）

需要 JDK 和 Android SDK，建议在装了 Android Studio 的电脑上操作：

```bash
VITE_API_BASE=https://<你的部署域名> npm run build
npx cap add android      # 只需执行一次
npx cap sync android
npx cap open android     # 在 Android Studio 里运行或打包
```
