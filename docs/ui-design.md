# UI 设计说明：两个视觉世界

给实现者看的。先读 `AGENTS.md` 和 `docs/pitch.md`。令牌（CSS 变量）都在 `src/index.css`，购物世界写在 `src/styles/shop.css`，审批世界写在 `src/styles/oa.css`。

## 一、为什么要两个世界

路演的一句话：平台用墙浪费你的注意力，用滑梯跳过你的判断，我们在滑梯上放一个问题。

观众要**看见**这件事：

- 购物世界是**滑梯**。暖色、顺滑、诱人，像一个普通的购物页，让人想点“立即购买”。
- 点下去不付款，页面一下变成灰白的公文。这一下**橙红变灰蓝**就是“滑梯上的问题”。
- 审批世界是**墙和问题**。灰白、正式、官腔：文号、审批人“AI 领导”、红色圆章。

一眼规则：橙红 = 想买；灰蓝公文 = 要被问话。

## 二、怎么切换世界

App 根节点 `.app` 加一个世界类：

| Screen | 世界 |
|---|---|
| `shop`、`product` | `world-shop` |
| 其余全部（新增的 `converted` 转办页、`gate`、`form`、`reviewing`、`rejected`、`approved`、`quiz`、`remarking`、`receipt`、`withdrawn`、`regulations`） | `world-oa` |

`:root` 默认就是审批世界的值，所以没加类的页面也不会坏。`gate`（广告和冷静）属于队友 B，别改它的样式；它读取 `--oa`、`--price`、`--text`，这三个变量的值不要动。

关键时刻的流程：商品页点“立即购买” → **转办页 `converted`**（审批世界）→ 点“开始办理” → 广告 `gate` → 申请单 `form`。这需要在 `src/flow.ts` 和 `src/App.tsx` 各加一个 `Screen` 变体和一个 case，由 App 实现者负责。

## 四、字号、间距

字号（基础字号 ≥ 16）：

| 令牌 | px | 用途 |
|---|---|---|
| `--fs-caption` | 13 | 最小字：出处、模拟声明 |
| `--fs-small` | 14 | 次要说明、表单标签 |
| `--fs-body` | 16 | 正文 |
| `--fs-lead` | 18 | h2、栏目标题 |
| `--fs-h1` | 24 | 页面标题 |
| `--fs-price` | 32 | 商品页大价格 |
| `--fs-display` | 40 | 倒计时数字 |

间距：`--sp-1..6` = 4 / 8 / 12 / 16 / 24 / 32。点击区域最小高度 `--tap` = 44px。页面左右边距 16px，最大宽度 430px，不允许横向滚动（`.app` 已设置 `overflow-x: clip`）。

## 五、组件

### 购物世界

- **商品卡片**：白底圆角 12px 加阴影；方图在上，名称两行截断，下面一行价格（红），再下面最多 2 个徽标。整张卡片可点，高度一致。
- **价格块**：小号 `¥`（约 0.6 倍）加大号红色数字（列表 20px，商品页 `--fs-price`）。价格后面可跟灰色小字“含必需配件与运费”之类的**真实**说明，不画划线价。
- **徽标 `.badge`**：圆角 6px，13px 字，高度 20px 左右。两种：淡橙底橙字；金色底深棕字。内容只用下面两类：
  - 真实数据：`details.quoteLabel`（如“官方报价”）、`details.priceNote`、商品分类 `product.category`、必需配件数量、运费（0 显示“包邮”）。`product.source === null` 时显示“示例价”。
  - 明显讽刺、不含事实断言的短句：“心动预警”“先别急”“冲动价”。禁止出现销量、折扣、好评率、“限时”“仅剩”等数字或事实。
- **底部购买栏 `.buybar`**：固定在屏幕底部，宽度 `min(100%, 430px)` 居中，白底，上方 1px 暖灰线，加底部安全区 `env(safe-area-inset-bottom)`。左边只放红色标价（不显示含配件的合计：真实总价是用户在申请单里自己算的，显示出来会让第三条驳回穿帮），右边大按钮“立即购买”，高度 48px，胶囊，橙红渐变，白字 18px 加粗。页面内容底部要留出栏的高度（约 88px），不能被盖住。
- **顶栏**：白底，左边店名“奇怪小店”（橙红加粗，点击回首页），右边“规章”和难度下拉保持可用，样式淡化（演示前要选难度，不能去掉）。

### 审批世界

- **公文纸 `.doc`**：白底，1px `--line` 边框，圆角 4px，内边距 16px，放在灰色页面上，纸与纸之间留 12px。
- **公文头 `.doc-head`**：顶部一行小字“个人钱包审批办公室”；下面是标题（如“采购申请单”）；再下面两行键值：**文号** `CG-YYYYMMDD-NNNN`（等宽字体 `--font-mono`），**审批人** `AI 领导`；底部一条 2px `--oa` 横线。
- **栏目标题 `.doc-section`**：`--surface-head` 底，左边 4px `--oa` 竖条，字 `--fs-lead` 加粗，上下内边距 8px。像表格的分区标题，例如“一、基本信息”“二、替代方案论证”。
- **键值表 `.doc-table`**：左列标签（灰，宽 5em），右列内容，行间 1px 虚线。
- **圆章 `.stamp-round`**：圆形双线边框，粗体字，旋转 -12°，半透明 0.9。三种：驳回（`--reject`）、同意（`--approve`）、审批专用章（`--reject`，用在回执）。**章必须在自己的预留框里（至少 96x96，加外边距），不能绝对定位压在文字上。**
- **选项 chip / 复核单选项**：白底细线，选中时 `--accent-soft` 底加 `--accent` 边和字，高度 ≥ 44px。
- **按钮**：每屏只有一个主按钮（蓝，纯色，圆角 4px，宽度满行）；次按钮白底蓝边；破坏性操作（撤回申请）用红字链接。
- **横幅 `.banner`**：驳回红底红字，通过绿底绿字；位于公文头下面，旁边或下方放对应的章。

## 六、通用规则（来自项目的 UI 规则）

1. 看颜色就知道在哪个世界：橙红暖色 = 购物；灰白加蓝 = 审批。
2. 只借通用电商习惯（暖色强调、红色价格、底部购买栏），不抄任何品牌的颜色、Logo、字标、页面布局。界面上不出现品牌名。
3. 每屏一个主行动。颜色按角色：主行动 / 驳回红 / 同意绿 / 官僚蓝 / 淡出灰。
4. 基础字号 ≥ 16，最小字 13，对比度够；最大宽度 430px；不横向滚动。
5. 摩擦是故意的，但永远要让人知道下一步做什么：每屏只有一个显眼的主按钮，标题说清楚这一步是什么。
6. 细节干净：不重叠（回执的章不能压住商品名），间距用令牌。
7. 不编造事实：没有销量、折扣、好评。徽标只用真实数据或明显的讽刺短句。
8. 界面文字用中文，代码和注释用英文。

## 七、分屏说明

### 购物世界（实现者 1，文件：`src/styles/shop.css`，`src/screens/Shop.tsx`、`ProductPage.tsx`）

**商品列表 Shop**

- 顶部一条小横幅：标题“今日精选”，副标一句讽刺但不含事实的话（如“好东西都在这里，想好了再点”）。去掉现在“所有购买均需提交采购申请”那句，因为这里是滑梯，不该提前吓人。
- 两列网格，卡片见上。图片 `ProductImage` 用 `thumb`；价格红色；最多 2 个徽标。
- 没有任何官僚元素：不出现“申请”“审批”“OA”。

**商品页 ProductPage**

- 大图（`large`），下面是价格块（大红价），再下面名称 h1，再下面徽标一行（`quoteLabel`、`priceNote`、必需配件数量、运费）。
- 采集日期和核算场景保留，用 13px 灰字放在价格块下面。这是真实数据来源，不能删。
- 配件、替代方案、“一个月后”等现有内容保留，放在“商品详情”白色卡片里，用普通栏目标题。不删数据，只是换成购物页的样子。
- 底部固定购买栏：主按钮“立即购买”（调用原来的 `onApply`）。**不要再显示“本页面不提供立即购买”那行字**，也不要出现“申请采购”。
- 点击后不付款，进入转办页（审批世界）。此处点击没有额外动画，越顺滑越好。

### 审批世界（实现者 2，文件：`src/styles/oa.css`，新增 `src/screens/Converted.tsx`，修改 `Decision.tsx`、`ProcurementForm.tsx`、`Quiz.tsx`、`Receipt.tsx`、`Regulations.tsx`，以及 `App.tsx`、`flow.ts` 加世界类和 `converted` 屏）

**转办页 Converted（关键时刻）**

- 整屏灰白公文：公文头（“个人钱包审批办公室”、文号 `CG-YYYYMMDD-NNNN`、审批人 AI 领导）。
- 大标题：**“您的购买请求已转为采购申请”**。
- 键值表：申请物品（商品名）、申报金额（商品标价，黑色，不是红色）、审批人（AI 领导）、状态（待办理）。
- 一句官腔说明：“根据《个人钱包管理暂行办法》，购买须先办理采购申请。”
- 一个主按钮：**“开始办理”**（进入 `gate`）。一个淡出的文字链接“返回商品页”。
- 文号只在进入此页时生成一次，之后表单页公文头沿用同一个。

**ProcurementForm 申请单**

- 公文头（标题“采购申请单”，文号，审批人，申请日期，第 N 次提交）。
- 用栏目标题分区：“一、申请事项”（采购用途、首次使用、使用频率）、“二、替代方案论证”（为什么不租、不借、现有的）、“三、金额申报”（申报总价）。
- chip 保持多选一；总价输入框右侧加单位“元”。底部一个主按钮“提交领导审批”。

**Reviewing / Remarking 审阅中、批示中**

- 公文纸中间放转圈，标题“领导审阅中”，小字“第 N 次提交 · 请勿关闭页面”，加文号。转圈用 `--oa`。

**Rejected 驳回**

- 公文头 + 驳回横幅，旁边（或横幅下方）放驳回章，章在预留框内，不压文字。
- “审批意见”用栏目标题，意见文字在带红色左竖线的框里。
- 按钮：主按钮“补充材料，重新提交”；次按钮“换个方案”；链接“查看《个人钱包管理暂行办法》”；红字链接“撤回申请”。

**Approved 通过**

- 绿色通过横幅加同意章；商品名、应付总额（黑色加粗）；主按钮“去下单”；下面 13px 声明“模拟订单，不会扣款，也不会发货”。

**Withdrawn 已撤回**

- 简洁的公文纸：标题“申请已撤回”，一句“恭喜您省下了这笔钱”，主按钮“返回首页”。

**Quiz 复核单**

- 公文头“采购复核单”，文号。每道题是一张 `.doc` 里的栏目：题号加题目为栏目标题，选项是整行可点的选项（≥ 44px），选中为淡蓝底。
- 答错：红边红底加红字解释；未作答：红边提示。“没有标准答案”标签用淡灰蓝。
- 底部一个主按钮“提交复核”。

**Receipt 回执**

- 公文头“采购审批回执”；键值表（单号、物品、金额、提交次数、审批意见）。
- **圆章“审批专用章”单独放在键值表下面，右对齐，有自己的预留框；不要再用绝对定位压在商品名上。**
- 声明“模拟订单：未扣款，不发货。”；主按钮“返回首页”（回到购物世界，这时应能感到“回到滑梯”）。

**Regulations 规章**

- 公文纸：居中标题《个人钱包管理暂行办法》，下面“个人钱包审批办公室 发布”；条款用“第×条”加粗的蓝色，条与条之间虚线；底部“已阅，返回”。
